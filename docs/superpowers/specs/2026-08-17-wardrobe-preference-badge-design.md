# 옷장 카드 선호도 미설정 배지 — 설계

**날짜**: 2026-08-17
**분류**: 사용자가 직접 제안한 6개 기능 중 1번(진행 순서 6→1→3→2→4→5의 두 번째).

## 배경

`/wardrobe/[id]`(옷 상세 페이지)에는 이미 "선호도" 섹션(`PreferenceForm`)이 있다 — 별점(1~5)·핏(작음/딱맞음/큼)·착용빈도(자주/가끔/거의 안 입음) 세 항목을 눌러서 저장한다. 이 값들은 핏 판단 엔진(`lib/fit/profile.ts`)이 "성공/실패 집합"을 가르는 원재료로 쓰인다(`rating>=4` 또는 `wear_frequency='often'`을 성공 신호로, `rating<=2` 또는 `wear_frequency='rarely'`를 실패 신호로 — `PreferenceForm.tsx` 주석 참고). 문제는 사용자가 옷을 등록만 하고 이 값을 채우지 않고 지나치기 쉽다는 것이다 — 옷장 목록(`/wardrobe`)에는 어느 옷의 선호도가 비어 있는지 알 방법이 없다.

## 요구사항

1. 옷장 목록(`GarmentCard`)에서 선호도가 비어 있는 옷을 한눈에 알 수 있어야 한다.
2. 그 표시를 누르면 해당 옷의 선호도 입력 화면으로 바로 이동해야 한다.

## 설계

### 1. "미설정" 판단 기준

`rating`(별점)이 `null`이면 미설정으로 본다. 핏 판단 엔진에서 별점이 가장 핵심적인 신호이고(향후 §10에 남겨둔 심각도·가중치 조정에서도 별점이 기준), 핏·착용빈도는 별점을 먼저 매기면 자연스럽게 따라오는 보조 정보로 취급한다 — 세 항목을 전부 강제하면 등록 직후 사용자가 배지를 없애려고 불필요하게 여러 번 클릭해야 한다.

### 2. 배지 위치와 문구

`GarmentCard`의 이미지 영역 우상단에 작은 배지를 오버레이한다. 문구: "선호도 미설정".

### 3. 컴포넌트 구조 변경

현재 `GarmentCard`는 카드 전체가 `<Link href="/wardrobe/{id}">` 하나로 감싸져 있다. 배지를 그 안에 중첩된 링크로 두면 `<a>` 안에 `<a>`가 되어 HTML 규격에 어긋나므로, 구조를 바꾼다:

- 바깥 요소를 `<div className={CARD_SURFACE}>`(카드 틀)로 바꾼다.
- 이미지+텍스트 블록은 기존처럼 `<Link href="/wardrobe/{id}">`로 감싼다 — 카드를 눌렀을 때의 동작은 그대로(상세 페이지 맨 위로 이동).
- `rating == null`일 때만, 이미지 영역 안에 `position: absolute`로 배치한 별도의 작은 `<Link href="/wardrobe/{id}#선호도">`를 오버레이로 추가한다. 이 링크를 누르면 상세 페이지의 "선호도" 섹션으로 바로 스크롤된다.

두 `<Link>`는 형제 관계로만 존재하고 서로 중첩되지 않는다.

### 4. 상세 페이지 앵커

`app/(app)/wardrobe/[id]/page.tsx`의 "선호도" `<section>`에 `id="선호도"`를 추가한다. 이 프로젝트의 (app) 레이아웃에는 sticky/fixed 헤더가 없으므로(확인됨) `scroll-margin-top` 같은 여백 보정은 필요 없다.

### 5. 데이터

`GarmentCardData`(`components/garment/GarmentCard.tsx`) 타입에 `rating: number | null`을 추가한다. `WardrobePage`(`app/(app)/wardrobe/page.tsx`)의 쿼리 `select`에 `rating`을 추가해 함께 내려받는다. 새 컬럼이나 마이그레이션은 필요 없다 — `garments.rating`은 계획 2부터 이미 존재한다.

## 영향 범위

- `/wardrobe` 목록의 카드 레이아웃만 바뀐다. `/wardrobe/[id]` 상세 페이지는 앵커 id 하나만 추가되고 나머지는 그대로다.
- 공유 옷장(`app/u/[share_slug]/page.tsx`)은 `GarmentCard`를 쓰지 않는다 — 자체 `PublicGarmentCard`를 따로 두고 있고 쿼리도 `rating`을 애초에 안 가져온다(확인 완료). 이번 변경이 방문자에게 선호도 정보를 노출할 위험은 없다.

## 테스트

`GarmentCard`는 순수 프레젠테이션 컴포넌트라 로직이랄 게 거의 없다(`rating == null` 조건 하나). 별도 단위 테스트보다는 `npm run build`(타입 체크) + 브라우저 확인(별점 없는 옷은 배지가 뜨고 누르면 선호도 섹션으로 스크롤되는지, 별점 있는 옷은 배지가 안 뜨는지, 카드의 나머지 영역을 눌렀을 때는 여전히 상세 페이지 맨 위로 이동하는지)으로 검증한다.
