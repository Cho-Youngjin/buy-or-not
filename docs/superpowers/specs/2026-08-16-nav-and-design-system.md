# 네비게이션 & 디자인 시스템 설계 문서

작성일: 2026-08-16

## 1. 배경

Plan 1~3 구현으로 스펙(§14 Phase 0-8)의 기능은 전부 갖춰졌지만, 실제로 써 보니 다음 문제가 있었다 (사용자가 직접 발견):

1. 옷장 상세 페이지(`/wardrobe/[id]`)에서 이전 화면으로 돌아갈 방법이 없다.
2. 옷장 화면 밖으로는 애초에 다른 페이지로 이동할 수 없다 — 화면 간 이동이 링크 하나 없이 전부 브라우저 주소창 의존.
3. 랜딩/옷장/로그아웃/마이페이지/추천룩 목록/살까말까 판단 화면이 서로 연결되어 있지 않다.
4. (별도 단계로 분리 — 2단계) 핏 판단 수치를 사용자가 직접 설정할 수 있는 화면이 없다.
5. 전반적인 UI가 완성도 없이 Tailwind 기본 회색/검정만 쓰고 있다.

이 문서는 1·2·3·5번을 묶은 **1단계(네비게이션 + 디자인 시스템)**를 다룬다. 4번(핏 판단 설정)은 이 문서가 만드는 네비게이션에 진입점만 마련해 두고, 별도 브레인스토밍·스펙·계획으로 2단계에서 다룬다.

## 2. 범위

**포함**
- 인증된 사용자가 쓰는 모든 화면(`/wardrobe`, `/wardrobe/[id]`, `/analyze`, `/cart`, `/looks`, 신설 `/mypage`)에 공통 헤더(PC)/하단 탭바(모바일) 적용
- 공개 공유 옷장(`/u/[share_slug]`)에 최소 헤더(로고 + 로그인 상태에 따른 링크) 적용
- 로그아웃 기능 신설 (지금은 앱에 로그아웃 자체가 없음)
- `/mypage` 신설: 프로필, 옷장 공개 토글(기존 `/wardrobe`에서 이동), 핏 판단 설정 진입점(비활성, 2단계 예고), 로그아웃
- 디자인 토큰(색상/타이포/모서리/간격) 정의 및 전 화면 적용
- 공통 UI 프리미티브(`Button`, `Card`, `Pill`) 신설 및 기존 컴포넌트 전면 교체

**제외**
- 핏 판단 수치 설정 화면 (2단계)
- 페이지 구조/레이아웃 자체의 재설계 (예: 옷장 화면을 그리드에서 다른 레이아웃으로 바꾸는 것) — 색상·타이포·모서리·버튼/카드 스타일만 통일하고 기존 화면 구조는 유지
- framer-motion 등 애니메이션 라이브러리 도입 — 순수 CSS transition만 사용

## 3. 디자인 토큰

`app/globals.css`의 `@theme inline`에 정의한다 (Tailwind v4 CSS-first 방식, 기존 `--color-background`/`--color-foreground` 대체).

| 토큰 | 값 | 용도 |
|---|---|---|
| `--color-canvas` | `#f7f5f0` | 페이지 배경 (웜크림) |
| `--color-surface` | `#ffffff` | 카드/입력 배경 |
| `--color-ink` | `#28261f` | 본문 텍스트 (순검정 금지 — 웜 차콜) |
| `--color-ink-muted` | `#8a8677` | 보조 텍스트 |
| `--color-border` | `#e4e0d6` | 헤어라인 보더 |
| `--color-accent` | `#c1502e` | 주요 CTA, 활성 탭, 링크 (테라코타) |
| `--color-accent-ink` | `#ffffff` | accent 배경 위 텍스트 |

- Cursor 마케팅 사이트(`DESIGN-cursor.md`)의 정확한 오렌지(`#f54e00`)는 그대로 쓰지 않는다 — "따뜻하고 채도 낮은 단일 포인트색" 원칙만 가져오고, 색 자체는 이 앱만의 테라코타로 구분한다 (브랜드 색 복제 회피).
- 버튼 radius `8px`, 카드 radius `12px`. 그림자 대신 `border-(--color-border)` 헤어라인만 사용 (드롭섀도 금지).
- 숫자(가격, 치수, %)는 `font-mono`(Geist Mono, 이미 로드되어 있음) 적용.
- `VerdictBadge`의 초록(살만함)/호박(주의)/빨강(비추천) 3색은 유지 — 의미 전달용 시맨틱 컬러로, "액센트 1개" 원칙의 명시적 예외.
- 다크모드: 기존 `prefers-color-scheme: dark` 분기는 제거한다 — 이 앱은 라이트 전용 웜톤 팔레트로 통일하고, 다크모드는 스코프 밖으로 둔다 (스펙에 없던 요구사항을 임의로 추가하지 않음).

## 4. 네비게이션 구조

### 4.1 라우트 그룹

인증된 화면을 `app/(app)/` 라우트 그룹으로 이동한다: `wardrobe/`, `wardrobe/[id]/`, `analyze/`, `cart/`, `looks/`, 신설 `mypage/`. 이 그룹의 `layout.tsx`가 공통 헤더/하단 탭바를 렌더링한다. 그룹 이동은 URL 경로에 영향을 주지 않는다 (Next.js 라우트 그룹 관례).

- `app/page.tsx`(로그인 전 랜딩), `app/auth/callback`: 그룹 밖에 그대로 둔다 — 로그인 전이라 탭 자체가 의미 없음.
- `app/u/[share_slug]`: 그룹 밖에 둔다. 방문자가 비로그인일 수 있어 "내 탭"을 전제하는 하단 탭바는 맞지 않는다. 대신 로고 + (로그인 상태면 "내 옷장으로" 링크 / 비로그인이면 로그인 버튼)만 있는 얇은 전용 헤더를 별도로 붙인다.

### 4.2 헤더/탭바 구성

5개 목적지, PC(header, `md:` 이상)와 모바일(하단 고정 탭바, `md:` 미만)에 동일하게 매핑한다:

| 목적지 | 경로 |
|---|---|
| 옷장 | `/wardrobe` |
| 살까말까 | `/analyze` |
| 장바구니 | `/cart` |
| 룩 | `/looks` |
| 마이페이지 | `/mypage` |

- 현재 경로는 `--color-accent`로 강조, 나머지는 `--color-ink-muted`.
- PC 헤더: 좌측 로고("살까 말까", `/wardrobe`로 링크) + 우측 수평 메뉴.
- 모바일 탭바: 화면 하단 고정, 아이콘 + 라벨 5개. 아이콘은 `@phosphor-icons/react`를 새로 설치해서 쓴다 (`package.json`에 아이콘 라이브러리가 없음을 확인함).
- 하단 탭바 높이만큼 페이지 본문에 `pb-16`(모바일 한정) 여백을 둬서 콘텐츠가 탭바에 가려지지 않게 한다.

### 4.3 `/mypage` 신설

- 프로필: 구글 계정의 아바타 이미지 + 닉네임 표시 (Supabase Auth `user.user_metadata`에서 읽음, 별도 테이블 불필요).
- 옷장 공개 토글: 기존 `ShareToggle` 컴포넌트를 `/wardrobe` 페이지에서 이곳으로 이동.
- "핏 판단 설정 (준비 중)": 클릭 불가능한 비활성 항목. 2단계에서 실제 설정 화면으로 교체.
- 로그아웃 버튼: `LogoutButton` 컴포넌트 신설 — `supabase.auth.signOut()` 호출 후 `/`로 리다이렉트. 이 앱에는 현재 로그아웃 기능이 전혀 없음 (grep으로 확인됨).

### 4.4 뒤로가기 (문제 1)

`/wardrobe/[id]`를 포함한 상세류 화면에 "← 옷장으로" 같은 명시적 상단 링크를 추가한다. 브라우저 뒤로가기가 아니라, 항상 옷장 목록(`/wardrobe`)으로 돌아가는 고정 링크로 둔다 — 상세 페이지에 어떤 경로로 들어왔든 동작이 일관되도록.

## 5. 공통 UI 프리미티브

`components/ui/`에 3개만 신설한다 (필요한 만큼만 — 과설계 방지):

- **`Button`** (`variant: 'primary' | 'secondary'`): radius 8px, `active:scale-[0.98]`로 눌림 피드백. `LoginButton`, `LogoutButton`, `GarmentForm` 제출 버튼, `PreferenceForm`, `DeleteGarmentButton`, `ShareToggle`, `AnalyzeLinkBar`, `RecommendLinkBar`, `OutfitBuilder`의 버튼들이 이걸로 교체된다.
- **`Card`**: radius 12px, `border-(--color-border)` 헤어라인만, 그림자 없음. `GarmentCard`, `CartItemCard`가 이걸 쓴다.
- **`Pill`**: `VerdictBadge`(시맨틱 3색 유지), `ShareToggle`의 공개/비공개 배지, 카테고리 필터 칩이 이걸 쓴다.

프리미티브를 거치지 않는 나머지 텍스트/배경 클래스(`text-gray-500`, `bg-gray-100` 등)도 화면별로 전부 새 토큰(`text-ink-muted`, `bg-canvas` 등)으로 치환한다 — 옷장/상세/장바구니/살까말까/룩/공유옷장 전 화면 대상.

## 6. 상태 처리

기존 화면들의 로딩(`loading.tsx` 5개)은 이미 있으나 전부 `불러오는 중…` 텍스트뿐이다. 이번 작업에서 텍스트를 스켈레톤 UI로 바꾸지는 않는다 — 스코프 밖 (요청받지 않은 개선을 임의로 얹지 않음). 새로 만드는 `/mypage`와 네비게이션 자체에는 로딩 상태가 거의 없으므로(서버 컴포넌트, 즉시 렌더) 별도 `loading.tsx`는 필요 시에만 추가한다.

## 7. 검증 방법

- `npm run build` 클린 통과 (타입 에러 0개)
- `npm test` 회귀 없는지 (UI 변경이라 기존 테스트 스위트는 대부분 영향 없어야 함)
- 브라우저로 실제 로그인 후 PC/모바일 뷰포트 양쪽에서: 헤더/탭바 클릭으로 5개 목적지 모두 도달 가능한지, `/wardrobe/[id]`에서 옷장으로 돌아가지는지, `/mypage`에서 공개 토글·로그아웃이 실제로 동작하는지, 로그아웃 후 `/`로 리다이렉트되는지, 비로그인 상태로 `/u/[share_slug]` 방문 시 로그인 버튼이 뜨는지 확인
