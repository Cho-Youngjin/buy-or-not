# 비로그인 랜딩페이지 확장 — 설계

**날짜**: 2026-08-17
**분류**: 사용자가 직접 제안한 6개 기능 중 4번(진행 순서 6→1→3→2→4→5의 다섯 번째). 브레인스토밍 도중 "룩 만들기"가 실제로 자체 제작이 안 된다는 걸 발견해, 그걸 먼저 고치는 계획 16(7번)을 끼워 넣고 완료한 뒤 이어서 진행한다.

## 배경

`app/page.tsx`(비로그인 랜딩페이지)는 지금 태그라인 한 줄 + h1 + 설명 한 줄 + 로그인 버튼뿐이다. 이 앱이 정확히 어떻게 동작하는지(무신사 링크 하나로 시작한다는 것 이상으로), 어떤 부가 기능이 있는지 알려주는 내용이 없다.

## 결정 사항 (사용자 확인, 브라우저 목업으로 검증됨)

- 레이아웃은 지금과 같은 세로 한 줄(가운데 정렬된 좁은 컬럼)을 유지한다 — 히어로 아래로 3단계 가이드를 세로로 쌓고, 그 아래 부가 기능을 짧은 목록으로 나열한다.
- 3단계 가이드 + 부가 기능 소개 섹션을 넣는다.
- "핏 판단 엄격도 직접 조절" 항목은 랜딩페이지에서 뺀다(마이페이지 안에서만 알면 되는 설정이라 첫인상용 카피로는 부적절하다는 판단).
- "룩 만들기" 항목은 친구 추천을 언급하지 않고 자체 제작 기준으로 쓴다(계획 16 완료로 실제로 가능해졌다).

## 설계

### 최종 카피

**히어로** (기존 그대로 유지):
- 라벨: "무신사 링크 하나로 시작하는 옷장"
- h1: "살까 말까"
- 설명: "가진 옷을 옷장에 모아두면, 새로 사려는 옷이 내 사이즈와 스타일에 맞는지 알려드립니다."
- 버튼: 기존 `LoginButton`

**3단계 가이드**:
1. 무신사 링크로 옷장에 옷을 등록하세요 — 실측·사이즈가 자동으로 채워집니다
2. 별점으로 선호도를 남기세요 — 같은 카테고리 옷 3벌 이상이면 더 정확해져요
3. 사려는 옷 링크를 넣어 판단받으세요 — 사이즈·스타일이 맞는지 바로 알려드립니다

2번의 "3벌 이상" 문구는 실제 규칙(`MIN_OWNED_GARMENTS_FOR_FIT = 3`, `lib/fit/rules.ts`)과 정확히 일치한다 — 과장이 아니다.

**부가 기능 소개** ("이런 것도 할 수 있어요"):
- 옷장을 친구에게 공유하고 추천받기
- 가진 옷을 조합해 나만의 룩 만들기
- 담아둔 옷 가격이 내리면 확인하기

### 구현 방향

`app/page.tsx`에 정적 마크업만 추가한다 — 새 컴포넌트나 새 로직이 필요 없다. 3단계와 부가 기능은 각각 상수 배열로 선언해 렌더링한다(반복되는 카드 마크업을 map으로 뽑되, 데이터 자체는 하드코딩된 카피이므로 별도 파일로 분리하지 않는다 — 이 페이지 하나에서만 쓰는 정적 텍스트를 위해 새 데이터 모듈을 만드는 건 과하다).

## 영향 범위

- `app/page.tsx` 한 파일만 수정한다. 로그인 흐름(`LoginButton`)이나 다른 페이지는 손대지 않는다.

## 테스트

정적 마크업 추가라 순수 로직이 없다. `npm run build`(타입 체크) + 브라우저 확인(비로그인 상태로 `/`에 접속해 3단계와 부가 기능 목록이 뜨는지, 라이트/다크 양쪽에서 읽기 편한지)으로 검증한다.
